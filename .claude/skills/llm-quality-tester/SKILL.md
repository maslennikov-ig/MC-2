# LLM Quality Tester

Test and evaluate LLM model quality for course generation tasks.

## Metadata

- **Version**: 2.1.0
- **Invocation**: `/test-model <model-slug> [--scenario <name>] [--language <ru|en>]`
- **User-invocable**: Yes
- **Category**: Quality Assurance
- **Reference Model**: Определяется из `test-scenarios.json` (или последний Tier S/A из БД)

## Purpose

Комплексное тестирование качества генерации LLM моделей по единой методологии. Оценка проводится по балльной системе с акцентом на **качество контента** как главный критерий.

## Эталонная модель (Reference Model)

Эталонная модель выбирается **динамически** из базы данных:

```sql
-- Получить лучшую модель Tier S или A
SELECT model_slug, total_points, quality_tier
FROM llm_model_benchmarks
WHERE quality_tier IN ('S', 'A')
ORDER BY total_points DESC, test_date DESC
LIMIT 1;
```

### Требования к эталону

Модель может стать эталонной при:

- **Tier S или A** (≥80 баллов)
- **Стабильность языка**: Нет смешения языков (RU↔EN)
- **Нет truncation**: Текст не обрезается
- **3+ успешных теста** на разных сценариях

## Methodology v2.0 — Система оценки качества

### Философия оценки

**Главное = Качество материала для обучения человека**

Мы оцениваем не "технически корректный output", а **полезность для реального обучения**:

- Поймёт ли студент материал?
- Сможет ли применить на практике?
- Запомнит ли ключевые концепции?
- Не будет ли введён в заблуждение?

---

## Критерии оценки (100 базовых баллов)

### 1. СМЫСЛОВОЕ КАЧЕСТВО (35 баллов) — Главный критерий

**Что оценивается:**

- Глубина раскрытия темы
- Корректность информации
- Полнота покрытия материала
- Логические связи между концепциями
- Уровень экспертизы

**Шкала:**
| Баллы | Описание |
|-------|----------|
| 32-35 | Экспертный уровень: глубже чем учебники, уникальные инсайты |
| 26-31 | Отличная глубина: все ключевые аспекты, хорошая детализация |
| 20-25 | Хорошо: основное раскрыто, но без wow-эффекта |
| 14-19 | Базово: поверхностно, много пропусков |
| 7-13 | Слабо: очень поверхностно, мало полезного |
| 0-6 | Плохо: пустой или некорректный контент |

**Вопросы для судьи:**

- Можно ли по этому материалу реально научиться теме?
- Есть ли все необходимые концепции для понимания?
- Адекватна ли глубина для целевой аудитории?

---

### 2. ПРАКТИЧЕСКАЯ ЦЕННОСТЬ (25 баллов)

**Что оценивается:**

- Конкретные примеры и кейсы
- Actionable советы и алгоритмы
- Применимость в реальной работе
- Связь теории с практикой
- Задания для закрепления

**Шкала:**
| Баллы | Описание |
|-------|----------|
| 23-25 | Отлично: сразу можно применить, реальные кейсы из индустрии |
| 18-22 | Хорошо: хорошие примеры, понятно как использовать |
| 13-17 | Нормально: примеры есть, но абстрактные |
| 7-12 | Слабо: мало практики, в основном теория |
| 0-6 | Плохо: чистая теория без применения |

**Вопросы для судьи:**

- Может ли студент применить это завтра на работе?
- Понятно ли, как решать конкретные задачи?
- Есть ли шаги/алгоритмы действий?

---

### 3. СООТВЕТСТВИЕ ЗАДАНИЮ (15 баллов)

**Что оценивается:**

- Выполнение всех требований промпта
- Соблюдение формата (JSON schema)
- Правильная структура разделов
- Целевая аудитория учтена
- Соответствие языку (RU/EN)

**Шкала:**
| Баллы | Описание |
|-------|----------|
| 14-15 | Идеально: все требования выполнены |
| 11-13 | Хорошо: почти всё, мелкие отклонения |
| 8-10 | Нормально: основное выполнено, часть пропущена |
| 4-7 | Слабо: много не соответствует заданию |
| 0-3 | Плохо: проигнорировано задание |

**Проверяется автоматически:**

- JSON schema validation
- Наличие обязательных полей
- Формат Mermaid диаграмм
- Языковая консистентность

---

### 4. ОТСУТСТВИЕ ГАЛЛЮЦИНАЦИЙ (10 баллов)

**Что оценивается:**

- Фактическая корректность утверждений
- Отсутствие выдуманных цифр/статистик
- Корректные ссылки (если есть)
- Логическая непротиворечивость
- Нет "уверенного вранья"

**Шкала:**
| Баллы | Описание |
|-------|----------|
| 10 | Безупречно: всё проверяемо и корректно |
| 8-9 | Отлично: нет явных галлюцинаций |
| 6-7 | Хорошо: мелкие неточности |
| 3-5 | Проблемы: есть сомнительные утверждения |
| 0-2 | Критично: явные галлюцинации |

**Типичные галлюцинации:**

- "Исследование 2023 года показало..." (без источника)
- Конкретные цифры/проценты без обоснования
- Несуществующие термины/методологии
- Искажение известных концепций

---

### 5. СТРУКТУРА И НАВИГАЦИЯ (10 баллов)

**Что оценивается:**

- Логическая последовательность изложения
- Scaffolding (от простого к сложному)
- Наличие введения и выводов
- Связи между разделами
- Подзаголовки и навигация

**Шкала:**
| Баллы | Описание |
|-------|----------|
| 10 | Идеально: чёткая структура, легко читается |
| 8-9 | Хорошо: структура есть, мелкие недочёты |
| 6-7 | Нормально: понятно, но путанно местами |
| 3-5 | Слабо: хаотичная структура |
| 0-2 | Плохо: поток сознания, нет структуры |

---

### 6. ВИЗУАЛИЗАЦИЯ И ГРАФИКА (5 баллов)

**Что оценивается:**

- Качество Mermaid диаграмм
- Релевантность визуализаций
- Правильный синтаксис
- Помогает ли понять материал
- Нет лишних/бесполезных схем

**Шкала:**
| Баллы | Описание |
|-------|----------|
| 5 | Отлично: диаграммы помогают понять, синтаксис верный |
| 4 | Хорошо: полезные визуализации, мелкие недочёты |
| 3 | Нормально: есть, но не особо помогают |
| 1-2 | Слабо: синтаксические ошибки или неуместны |
| 0 | Нет диаграмм или все сломаны |

**Проверяется автоматически:**

- Mermaid syntax validation
- Escaped quotes detection (`\"`)
- Unclosed brackets

## Штрафные баллы (могут уйти в минус)

| Нарушение                    | Штраф | Описание                                   |
| ---------------------------- | ----- | ------------------------------------------ |
| **Критическая галлюцинация** | -15   | Выдуманный факт, представленный как истина |
| **Фактическая ошибка**       | -10   | Неверная информация                        |
| **Обрыв контента**           | -10   | Незаконченные предложения, truncation      |
| **Смена языка**              | -10   | RU↔EN внутри текста                       |
| **Сломанный JSON**           | -10   | Невалидный формат                          |
| **Сломанный Mermaid**        | -5    | Синтаксические ошибки в диаграммах         |
| **Плагиат промпта**          | -5    | Повторение инструкций как контент          |
| **Запрещённые фразы**        | -3    | "As an AI...", "I cannot...", etc.         |

| **Креативные примеры**   | +5-10  | Запоминающиеся аналогии               |
| **Безупречный стиль**    | +5     | Текст как от профессионального автора |
| **Практические шаблоны** | +5     | Готовые к использованию артефакты     |

## Tier система (финальная оценка)

| Tier  | Баллов | Рекомендация     | Действие                           |
| ----- | ------ | ---------------- | ---------------------------------- |
| **S** | ≥95    | Primary model    | Использовать в production          |
| **A** | 80-94  | Production ready | Использовать с минимальным review  |
| **B** | 65-79  | Acceptable       | Использовать с обязательным review |
| **C** | 50-64  | Fallback only    | Только при недоступности лучших    |
| **D** | <50    | Do not use       | Не рекомендуется                   |

## Тестовые сценарии

### 1. Full Generation (основной)

**Цель:** Полная генерация урока по реальной теме

**Промпт:**

```
Generate a complete lesson on "Inventory Management Optimization" for B2B logistics managers.
Include: theory, practical examples, ABC/XYZ analysis, KPIs, Mermaid diagrams.
Language: Russian. Format: Markdown with JSON metadata.
```

**Оценивается всё:** смысл, практика, структура, визуализация, галлюцинации

### 2. Metadata Generation

**Цель:** Генерация метаданных курса (заголовки, описания)

**Фокус:** Соответствие формату, краткость, отсутствие воды

### 3. Quiz Generation

**Цель:** Генерация тестовых вопросов

**Фокус:** Корректность ответов, разнообразие, сложность

### 4. Code Examples

**Цель:** Генерация примеров кода

**Фокус:** Работоспособность, best practices, документация

## Процесс тестирования

### Step 1: Подготовка

```bash
# Выбор модели
MODEL="deepseek/deepseek-v3.2"

# Выбор сценария
SCENARIO="full-generation"

# Язык
LANGUAGE="ru"
```

### Step 2: Генерация контента

1. Вызов API модели через OpenRouter
2. Замер времени генерации
3. Сохранение полного output

### Step 3: Автоматические проверки (Heuristic Filter)

- JSON schema validation
- Mermaid syntax check
- Language consistency
- Word count check
- Truncation detection

### Step 4: LLM-Judge оценка

1. Primary Judge оценивает по критериям
2. Secondary Judge оценивает независимо
3. При разнице >15% — Tiebreaker

### Step 5: Сохранение результатов

```sql
-- Benchmark record
INSERT INTO llm_model_benchmarks (
  model_slug, model_name, provider,
  total_points, quality_tier,
  score_semantic_quality,
  score_practical_value,
  score_task_compliance,
  score_no_hallucinations,
  score_structure,
  score_visualization,
  score_bonuses,
  score_penalties,
  test_session_id
) VALUES (...);

-- Full content sample
INSERT INTO llm_benchmark_samples (
  benchmark_id, scenario, output_content,
  judge_scores, final_score
) VALUES (...);
```

### Step 6: Обновление Leaderboard

- Обновить `/benchmarks` страницу
- Обновить LEADERBOARD.md
- Уведомить о новом результате
