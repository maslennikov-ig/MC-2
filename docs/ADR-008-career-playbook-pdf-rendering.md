# ADR-008: Career Playbook PDF Rendering

Date: 2026-08-11
Status: Proposed

## Context

Экспорт Role Guide в PDF реализован самописным конвертером Markdown → HTML в
`packages/course-gen-platform/src/services/career-playbook-pdf-template.ts`, который затем
печатается Chromium через Playwright (`career-playbook-pdf.ts`).

Представительный прогон 2026-08-11 (60 страниц, ревью в
`.codex/stages/mc2-db696.105/evidence/quality-review.md`) получил за качество PDF **2 / 5** и был
признан непригодным к публикации. Дефекты делятся на две группы.

### Группа 1: рендерер не знает часть Markdown

`renderMarkdownBody` (`:129-247`) обрабатывает только code fences, `#`, `##`, `###`, таблицы и
списки `-`/`*`. Всё остальное попадает в `paragraph.push(line.trim())` (`:234`) и печатается как
сырой текст. `renderInlineMarkdown` (`:68-73`) поддерживает `code`, `strong`, `em` — ссылки не
поддерживает вовсе.

Замер по сгенерированному документу:

| Конструкция         | Вхождений | Результат                                              |
| ------------------- | --------: | ------------------------------------------------------ |
| `#### `             |         3 | буквально `#### Bucket ...` на странице 14             |
| `---`               |         9 | буквально `---` на страницах 3, 21, 28, 31, 42, 55, 59 |
| Нумерованные списки |  37 строк | распадаются в отдельные абзацы                         |
| Вложенные списки    |  0 сейчас | схлопнулись бы                                         |
| `[текст](url)`      |  0 сейчас | напечатались бы как сырой текст                        |
| Blockquote          |  0 сейчас | напечатался бы с `>`                                   |

Последняя строка — блокер для работы по обоснованности: контракт качества требует ссылок `[Sn]` на
источники, а рендерер их не поддерживает.

### Группа 2: печатный CSS ломает пагинацию

| Правило                                                           | Строка     | Следствие                                                                                                             |
| ----------------------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------- |
| `.playbook-block-heading { break-before: page }`                  | `:328`     | Каждый из 26 блоков начинает новую страницу; вместе с `break-inside: avoid` даёт полностью пустые страницы 20, 34, 57 |
| `break-inside: avoid` у `table`, `.code-block`, `.mermaid-figure` | `:338,347` | Крупный элемент выталкивается на следующую страницу, оставляя пустой остаток                                          |
| `.mermaid-diagram svg` без `max-height`                           | `:363`     | Диаграмма выше страницы режется — схема пересмотра разорвана между страницами 58-59                                   |
| Нет `orphans`/`widows`                                            | —          | Хвост FMEA на четверть страницы 50, продолжение FAQ на несколько строк страницы 42                                    |
| `font-family: Inter, Arial, sans-serif`                           | `:274`     | Нет символьного покрытия: 21 вхождение ✅/⚠️ вырождается в квадраты на странице 32                                    |

## Decision

### 1. Заменить самописный парсер на `marked` с кастомным рендерером

Добавить `marked` в зависимости `packages/course-gen-platform`. Разобрать Markdown им, а не
построчным циклом, сохранив три существующие интеграции через кастомный рендерер:

- **Фигуры Mermaid.** Fenced-блок с языком `mermaid` рендерится как
  `<figure class="mermaid-figure">` с `data-mermaid-source` — контракт, который читает
  `renderMermaidDiagrams` в `career-playbook-pdf.ts:118-158`. Не менять.
- **Идентификаторы заголовков.** `##`-заголовки блоков получают `id="block-N"` и класс
  `playbook-block-heading` — на них ссылается оглавление (`renderTableOfContents:260-267`).
  Нумерация та же: `header` пропускается, остальные считаются по порядку.
- **`PRINT_CSS`.** Остаётся в файле, правится по разделу 2 ниже.

Включить GFM (таблицы, зачёркивание, автолинки). Ссылки рендерятся в `<a href>`; для PDF внешние
ссылки дополнительно показываются как видимый URL в разделе «Источники» блока 25 — кликабельность
в PDF не гарантирована во всех просмотрщиках.

**Почему не расширение существующего парсера.** Наблюдаемый класс отказа — «модель выдала валидный
Markdown, которого рендерер не знает». Дописать шесть веток закрывает шесть известных случаев, но
не закрывает класс: следующая формулировка промпта или другая модель выдаст седьмой. Полноценный
парсер закрывает класс целиком.

**Почему `marked`, а не remark/rehype.** В `packages/web` уже стоит стек remark/rehype, но он
тянет `unified`-конвейер и ESM-плагины, избыточные для одного серверного преобразования.
`marked` — один пакет, синхронный API, встроенный GFM, простая замена рендерера.
`dompurify` в платформе уже есть, если понадобится санитизация.

**Допустимая альтернатива.** Если добавление зависимости в платформу нежелательно по политике
репозитория, допустимо дописать недостающие ветки в существующий рендерер (h4-h6, `hr`,
нумерованные и вложенные списки, ссылки, blockquote). В этом случае регресс-фикстура из раздела 3
обязательна и должна покрывать те же конструкции.

### 2. Переписать правила печати

```css
/* было: каждый блок — новая страница */
.playbook-block-heading {
  break-before: page;
}

/* стало */
.playbook-block-heading {
  break-before: auto;
  break-after: avoid;
}
p,
ul,
ol {
  orphans: 3;
  widows: 3;
}
.mermaid-diagram svg {
  max-width: 100%;
  max-height: 200mm;
  height: auto;
}
table {
  break-inside: auto;
}
thead {
  display: table-header-group;
} /* повтор шапки при разрыве таблицы */
tr {
  break-inside: avoid;
}
```

- `break-before: auto` вместо безусловного разрыва убирает пустые страницы; `break-after: avoid`
  не даёт заголовку остаться в одиночестве внизу страницы.
- `max-height: 200mm` при `height: auto` масштабирует высокую диаграмму вместо обрезки.
- Разрыв таблиц по строкам с повтором `<thead>` устраняет выталкивание длинных таблиц целиком.

### 3. Шрифт с символьным покрытием

Подключить в контейнер и в `font-family` шрифт, покрывающий используемые символы (Noto Sans +
Noto Sans Symbols 2, либо DejaVu Sans). Проверить, что образ Playwright/Chromium в
`packages/course-gen-platform` содержит эти шрифты; при отсутствии — добавить в Dockerfile.

Запасной вариант, если шрифт добавить нельзя: детерминированно заменять ✅/⚠️/❌ на текстовые
метки на этапе финальной сборки. Замена делается в одном месте (`final-assembler.ts`), а не в
промптах, чтобы Markdown-выгрузка оставалась читаемой.

### 4. Регресс-фикстура

Тест-фикстура — эталонный Markdown, содержащий все поддерживаемые конструкции: h1-h6,
нумерованные, маркированные и вложенные списки, `hr`, blockquote, GFM-таблицу, inline-код,
fenced-код, Mermaid-диаграмму, ссылку, символы ✅/⚠️.

Проверяется:

1. **HTML.** Ни одной строки сырого Markdown в выводе (нет `^#{1,6} `, `^---$`, `^\d+\. `,
   `[текст](url)` вне `<a>`).
2. **PDF.** Отрендерить страницы и убедиться, что нет полностью пустых; диаграмма не разорвана.
3. **Оглавление.** Число пунктов совпадает с числом блоков; каждый `href` соответствует
   существующему `id`.

Файл: `packages/course-gen-platform/tests/unit/services/career-playbook-pdf.test.ts` (расширение
существующего) плюс фикстура рядом.

## Consequences

**Положительные**

- Закрывается весь класс «неизвестная Markdown-конструкция», а не шесть известных случаев.
- Разблокируется работа по цитированию источников: ссылки начинают рендериться.
- Пустые страницы, разорванные диаграммы, сироты и квадраты вместо глифов устраняются правилами
  печати, а не подгонкой контента.

**Отрицательные и риски**

- Новая зависимость в `course-gen-platform`. Митигируется: один пакет без транзитивного дерева,
  синхронный API.
- Кастомный рендерер `marked` нужно покрыть тестами на контракт Mermaid и id заголовков — иначе
  сломается оглавление и отрисовка диаграмм. Это прямо закрывается фикстурой из раздела 4.
- Отказ от безусловного разрыва страниц перед блоком меняет визуальный ритм документа: блоки
  перестанут всегда начинаться с новой страницы. Это осознанный обмен: пустые страницы хуже
  плотной вёрстки. Если по итогам приёмки ритм окажется важен, вернуть разрыв точечно для
  крупных блоков, а не для всех 26.
