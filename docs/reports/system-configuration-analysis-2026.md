# Анализ Сценариев и Конфигурации MegaCampus AI (Январь 2026)

_Документ составлен на основе актуальной технической документации (январь 2026), включая спецификации автоматического режима, редизайна UI и исследований RAG vs KAG._

---

## Блок 1: Портрет и Сценарии использования

### 1. Какую бизнес-задачу чаще всего будет решать пользователь?

Платформа технически и методологически разделяет задачи на два основных потока:

#### А. Hard Skills / Onboarding (Регламенты, Инструкции, Продуктовое обучение)

- **Режим генерации:** **Document-Based Generation**.
- **Технология:** Используется **Advanced RAG** с иерархическим чанкингом (Parent/Child Indexing) и **Late Chunking** (Jina-v3). Это критично для точности: система "привязывает" каждый сгенерированный факт к конкретному абзацу исходного документа.
- **Нововведение (Январь 2026):** Внедрена функция **Semantic Diffing**. Если регламент обновился, система показывает не просто разницу в тексте, а концептуальные изменения в смысле обучения, позволяя обновлять только устаревшие части курса.
- _Источник:_ `docs/INVESTOR-PITCH-RU.md`, `docs/specs/SPEC-2025-12-05-stage4-stage5-ui-redesign.md` (Раздел 2.10).

#### Б. Soft Skills (Управление, Лидерство, Коммуникации)

- **Режим генерации:** **Topic-Only Generation**.
- **Технология:** Использует "собственные знания" больших моделей (DeepSeek V3 / Qwen 2.5) с опциональным RAG-поиском по внешним источникам.
- **Методология:** Применяется подход **Skeleton-of-Thought (SoT)** — сначала генерируется логический "скелет" мысли и аргументации, а затем он наращивается контентом. Это обеспечивает строгую логическую связность и отсутствие "вода", свойственной обычным LLM.
- _Источник:_ `docs/research/010-stage6-generation-strategy/LLM Content Generation Strategy Research.md`.

### 2. Кто будет основным оператором системы?

В системе реализовано жесткое разделение интерфейсов для двух ролей (Hybrid UI):

#### Линейный руководитель («Быстро и просто»)

- **Инструмент:** **Automatic Mode** (внедрен 14.01.2026).
- **Сценарий:** Загрузка файла → Просмотр предварительной стоимости (~$0.50) → Нажатие кнопки "Start" → Получение уведомления о готовности.
- _Источник:_ `docs/features/automatic-generation-mode.md`.

#### Профессиональный методист / HR («Тонкие настройки»)

- **Инструмент:** **Semi-Automatic Mode** с интерфейсом **Graph View**.
- **Сценарий:** Детальная настройка "Графа знаний" (Dependency Graph), редактирование "Педагогической стратегии" и использование **Inline Regenerate Chat** для точечных правок контента.
- _Источник:_ `docs/specs/SPEC-2025-12-05-stage4-stage5-ui-redesign.md`.

## Блок 2: Работа с исходными данными (Контент)

### 3. В каком виде у компании обычно хранятся знания?

Система использует движок **IBM Docling**, позволяющий обрабатывать широкий спектр форматов:

- **Текстовые регламенты:** PDF (с OCR для сканов), DOCX, Markdown, TXT.
- **Ссылки на базу знаний:** Полная поддержка **HTML**. Система парсит веб-страницы и документацию по ссылкам.
- **Презентации:** PPTX (преобразование слайдов в учебные модули).
- **Таблицы:** XLSX (извлечение данных с сохранением структуры ячеек).
- **Изображения:** OCR и Vision AI извлекают текст из PNG/JPG схем и диаграмм.
- **Видеозаписи встреч:** ⚠️ **На текущий момент (январь 2026) видео-вход не поддерживается напрямую для транскрибации в текст в основном пайплайне.** Whisper используется в проекте только для _выходной_ генерации видео (Stage 7).
- _Источник:_ `docs/INVESTOR-PITCH-RU.md` (Раздел "Docling"), `docs/REQUIREMENTS.md`.

### 4. Насколько строго ИИ должен придерживаться материалов?

- **Строгий режим (Document-Based):** Используется **Optimized RAG**. Точность поиска фактов составляет **85-90%**.
  - **Strict Mode:** ИИ отвечает _только_ по документам. При отсутствии информации модель пишет: "В документах информация не найдена", исключая галлюцинации.
  - **Citation Links:** Каждое утверждение снабжается ссылкой на конкретную страницу PDF/источник.
- **Режим импровизации (Topic-Only):** Допускается дополнение из знаний LLM, но результат проходит через **Factual Accuracy Verifier** (проверка фактов).
- _Источник:_ `docs/research/RAG-vs-KAG-ANALYSIS.md`, `docs/INVESTOR-PITCH-RU.md`.

## Блок 3: Методология и Проверка знаний

### 5. Какая глубина проверки знаний требуется?

Функционал проверки знаний (Stage 7 Enrichments) включает:

- **Генератор Квизов (Quiz Generator):** Создает вопросы трех типов: `multiple_choice`, `true_false`, `short_answer` (открытые вопросы).
- **Ситуационные кейсы:** Поддерживаются педагогические стили `problem_based` и `case_based`, которые генерируют задачи на решение ситуаций.
- **Bloom's Alignment:** Вопросы распределяются по уровням: Remember (30-40%), Understand (30-40%), Apply/Analyze (20-30%).
- _Источник:_ `packages/course-gen-platform/src/stages/stage7-enrichments/prompts/quiz-prompt.ts`.

### 6. Нужна ли функция «Стоп-урока»?

**Да, функция реализована на уровне графа зависимостей.**

- В структуре данных есть поле **`prerequisites`**.
- В интерфейсе реализованы связи типа **`PREREQUISITE_FOR`**.
- Это позволяет LMS блокировать доступ к следующему модулю, пока не выполнены условия предыдущего (сдача теста или изучение контента).
- _Источник:_ `packages/shared-types/src/common-enums.ts`, `docs/specs/SPEC-2025-12-05-stage4-stage5-ui-redesign.md` (Раздел 2.8).

### 7. Как ИИ должен определять стиль общения (Tone of Voice)?

- **Smart Context Router (Авто):** Система анализирует стиль загруженных документов и предлагает его копировать (Stage 4).
- **Пресеты (Вручную):** Пользователь выбирает из **19 пресетов** (Academic, Conversational, Storytelling, Socratic и др.).
- **Tiered Context:** При правках ("Сделай веселее") система использует 4-уровневый контекст для сохранения единства тона (от уровня абзаца до уровня бренда).
- _Источник:_ `docs/specs/SPEC-2025-12-05-stage4-stage5-ui-redesign.md` (Раздел 2.7).
