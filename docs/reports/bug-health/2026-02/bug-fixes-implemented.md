## High Priority (3 bugs assigned)

### BUG-004: N+1 Database Queries in Stage 5 Materialization [FIXED]

- **File**: `packages/course-gen-platform/src/stages/stage5-generation/handler.ts`
- **Lines changed**: 830-990 (replaced ~55 lines with ~170 lines)
- **Root cause**: Nested `for...of` loops with individual `await supabaseAdmin.from().insert()` calls. For a course with N sections and M lessons per section, this produced N + (N\*M) individual DB round trips (e.g., 110 queries for 10 sections x 10 lessons).

**Fix implemented**:

1. Build an array of section payloads from `sanitizedStructure.sections`
2. Batch insert all sections in ONE `.insert(sectionPayloads).select('id, order_index')` call
3. Map returned section IDs by `order_index` to associate with lessons
4. Build an array of lesson payloads using the mapped section IDs
5. Batch insert all lessons in ONE `.insert(lessonPayloads)` call
6. On batch failure: falls back to original individual insert pattern (graceful degradation)

**Before** (110 queries for 10x10 course):

```typescript
for (const section of sanitizedStructure.sections) {
  const { data: newSection } = await supabaseAdmin
    .from('sections').insert({...}).select('id').single();  // N queries
  for (const lesson of section.lessons) {
    await supabaseAdmin.from('lessons').insert({...});       // N*M queries
  }
}
```

**After** (2 queries for any course size):

```typescript
// 1 query: batch insert all sections
const { data: insertedSections } = await supabaseAdmin
  .from('sections')
  .insert(sectionPayloads)
  .select('id, order_index');

// 1 query: batch insert all lessons
await supabaseAdmin.from('lessons').insert(lessonPayloads);
```

**Preserved behavior**:

- `materializedSections` and `materializedLessons` counters still tracked
- try/catch wrapper maintained (materialization is non-fatal per original design)
- Success/failure logging preserved
- Error messages preserved for individual fallback path
