# Code Review: Duplicate Learning Objectives Fix + Next Lesson UI Card

**Date**: 2026-02-18
**Reviewer**: Code Reviewer Worker
**Scope**: staged changes — 4 files
**Depth**: thorough

## Summary

The changeset addresses three problems: duplicate learning objectives appearing both in the UI card and in LLM-generated intro text, verbose/unfocused conclusion generation, and the absence of a "Next Lesson" UI card after lesson content.

The prompt changes are effective. The UI addition is functionally correct. Several issues were found across Warning and Improvement severity; there are no Critical (blocking) bugs, but two Warnings carry real UX risk.

## Warnings

### W-1: `serial_generator` prompt still instructs LLM to "tease next lesson" in conclusion sections

**File**: `packages/course-gen-platform/src/shared/prompts/stage6-prompts.ts`, line 163

**Finding**: The `stage6_single_call_generator` prompt was correctly updated (line 401 now says "DO NOT preview next lesson"). However, the `stage6_serial_generator` prompt — which is the **active** prompt used by the section-by-section generator (`generator-section.ts` confirmed at line 206) — still contains the old instruction:

```
- In conclusion sections, tease next lesson: "In the next lesson, we will explore [next_lesson.title]..."
```

This means lessons generated via the serial path will still have LLM-written next-lesson teasers in their conclusion sections, while the new UI card simultaneously displays the same information. The duplication problem is only half-fixed.

**Impact**: Lessons generated by `stage6_serial_generator` will show "next lesson" text both inside the lesson body and in the new UI card.

**Fix**: Apply the same change from the single-call generator to line 163 of `stage6_serial_generator`:

```
- In conclusion sections, write ONLY short bullet-point takeaways. Do NOT preview the next lesson — a separate UI element handles this.
```

### W-2: Migration files retain the old "tease next lesson" instruction and will be re-seeded

**Files**:

- `packages/course-gen-platform/supabase/migrations/20260114150000_add_style_prompt_to_stage6_generator.sql` (line 147)
- `packages/course-gen-platform/supabase/migrations/20260109190000_update_stage6_rag_validation.sql` (line 129)
- `packages/course-gen-platform/supabase/migrations/20260108120000_seed_stage6_serial_generator.sql` (line 109)

**Finding**: These migration files seed the `prompt_templates` table in Supabase with the old `stage6_serial_generator` text. The hardcoded TypeScript prompts are the runtime source of truth, but a new environment setup (or a branch reset) will seed the old text into the DB. If any part of the system still reads prompts from the database rather than from the TypeScript registry, the old behavior will re-appear.

**Impact**: Risk of regression in newly provisioned environments. Also causes misleading documentation-in-code: migrations appear to describe current behavior but do not.

**Fix**: Update the relevant migration SQL files to match the corrected `stage6_serial_generator` prompt text, or add a new migration that patches the `prompt_templates` row.

### W-3: Test script `test-single-call-generation.ts` uses the old prompt structure

**File**: `packages/course-gen-platform/scripts/test-single-call-generation.ts`, line 475

**Finding**: This script builds its own inline prompt string (not from the shared prompt registry) and still reads:

```
1. ## ${headers.introduction} — Hook (${spec.intro_blueprint.hook_strategy}) + preview of learning objectives (100-150 words)
3. ## ${headers.summary} — Brief recap + next steps (80-120 words)
```

Both instructions contradict the production changes: the introduction still previews objectives and the summary uses the old "brief recap + next steps" format instead of bullet-point takeaways.

**Impact**: Test outputs will not match production behaviour. Developers using this script to validate generation quality will get misleading results.

**Fix**: Update the inline prompt in the test script to mirror the production `stage6_single_call_generator` structure: remove "preview of learning objectives" from the intro instruction and replace "Brief recap + next steps (80-120 words)" with "Bullet-point list of 3-5 key takeaways (40-80 words)".

### W-4: `LessonView` (focus mode path) wraps `LessonContent` in a `prose` div, causing double styling

**File**: `packages/web/components/course/viewer/components/LessonView.tsx`, lines 184-193

**Finding**: In focus mode, `LessonContent` is rendered inside:

```tsx
<div className="prose prose-lg dark:prose-invert prose-purple max-w-none">
  <LessonContent ... />
</div>
```

`LessonContent` itself already contains its own `prose prose-lg dark:prose-invert prose-purple max-w-none` div for the main content (line 406 of `lesson-content.tsx`). The new "Next Lesson" card (lines 411-436) is a sibling to that prose div inside `LessonContent`, meaning it inherits the outer `prose` wrapper's typography in focus mode but not in the normal (tab) mode path. This produces inconsistent card typography between the two rendering paths.

**Impact**: The "Next Lesson" card may render with prose-scaled font sizes and line heights in focus mode only. Visually subtle but inconsistent.

**Fix**: Remove the outer `prose` wrapper from the `LessonContent` call in focus mode (lines 184-194 of `LessonView.tsx`). `LessonContent` manages its own prose scoping internally.

## Improvements

### I-1: Hardcoded Russian strings — "В следующем уроке", "Цели урока", "Дополнительные материалы"

**File**: `packages/web/components/common/lesson-content.tsx`, lines 380, 416, 237

**Finding**: Three user-visible strings are hardcoded in Russian with no i18n:

- `"Цели урока"` (line 380) — the learning objectives card header
- `"В следующем уроке"` (line 416) — the new next lesson card header
- `"Дополнительные материалы"` (line 237) — the additional materials header

The project uses `next-intl` (confirmed by `packages/web/messages/ru/` message files), and other components in the codebase use `useTranslations`. The `lesson-content.tsx` file accepts `courseLanguage` as a prop already, suggesting awareness of multi-language content.

A key in `messages/ru/generation.json` already exists at `"lessonObjectives": "Цели урока"` (line 250), indicating this label was anticipated for i18n but not wired up in the component.

**Recommendation**: Use `next-intl`'s `useTranslations` hook and define keys for all three strings. At minimum add `"nextLesson"` and `"additionalMaterials"` keys alongside the existing `"lessonObjectives"` key.

### I-2: `objectives` on the next lesson could be `null | undefined | string[]` — no guard in type

**File**: `packages/web/components/common/lesson-content.tsx`, lines 43-44 and 421-423

**Finding**: The `nextLesson` prop is typed as:

```tsx
nextLesson?: {
  title: string
  objectives?: string[] | null
}
```

The guard at line 421 (`nextLesson.objectives && nextLesson.objectives.length > 0`) is correct. However, `allLessonsOrdered[currentIndex + 1].objectives` in `LessonView.tsx` (line 94) is passed directly from the database `Lesson` type. If the `Lesson.objectives` database column can be `null` (which Supabase nullable columns return as `null`, not `undefined`), the union type `string[] | null` must remain in the interface. This is currently handled correctly.

The improvement is to add a JSDoc comment on the interface field clarifying it can be null (database origin), since future maintainers may simplify the type and break the guard:

```tsx
/** Null when lesson has no objectives set (database column is nullable) */
objectives?: string[] | null
```

**File**: `packages/course-gen-platform/src/shared/prompts/stage6-prompts.ts`, lines 547-549

### I-5: "Next Lesson" card appears in the middle of the page in focus mode due to wrapping layout

**File**: `packages/web/components/course/viewer/components/LessonView.tsx`, lines 184-232

**Finding**: In focus mode, `LessonContent` is rendered inside a `max-w-6xl` container (line 162), and the "Next Lesson" card renders at the bottom of the `LessonContent` div. Immediately below it (lines 196-232), the focus-mode navigation bar ("Предыдущий урок" / "Следующий урок") also appears with `mt-16`. The two "next lesson" elements — the card and the navigation label — now stack visually, both pointing to the same lesson. This is redundant UX.

**Recommendation**: In focus mode, suppress the "В следующем уроке" card (pass `nextLesson={undefined}` to `LessonContent` in the focus mode branch) since the navigation bar already provides that affordance. In the tab mode (normal view), the navigation bar is not visible in the content tab, so the card is the only "next lesson" indicator and should remain.

## Prompt Quality Assessment

### `stage6_single_call_generator` (active, primary)

The two prompt changes are clear and actionable for LLMs:

- Line 365: Removing "preview of learning objectives" from the intro instruction is unambiguous. The added note "they are displayed separately in the UI above the lesson content" gives the model a rationale, which helps compliance.
- Line 369: "Bullet-point list of 3-5 key takeaways from this lesson (what the reader learned). Total: 40-80 words. IMPORTANT: Do NOT restate or paraphrase content from earlier sections. Use SHORT thesis-style bullets only (one line each). Do NOT include 'next lesson' preview" is specific enough. The dual constraint (short bullets + no next-lesson) is well-stated.
- Line 401: The in-rules reinforcement "Do NOT preview the next lesson — a separate UI element handles this" is a good pattern for high-compliance rate.

One minor gap: the word budget instruction at line 362 says "Target: approximately {{targetWordCount}} words total (excluding exercises and digest)" but the summary is also excluded from that total (it has its own 40-80 word budget). The parenthetical should read "(excluding intro, summary, exercises, and digest)" to match the variable `sectionsWordBudget` description on line 484.

### `stage6_serial_generator` (active, serial path)

Not updated. See W-1 above.

## Design Consistency

The new "В следующем уроке" card follows the established visual pattern from the existing "Цели урока" card:

- Same `rounded-xl border ... bg-gradient-to-br ... p-6 shadow-sm transition-shadow hover:shadow-md` pattern
- Same icon-heading row layout
- Consistent dark mode tokens (`dark:border-*`, `dark:from-*`, `dark:to-*`)

The only minor design deviation: the objectives card uses `dark:text-gray-300` for list items while the next-lesson card uses `dark:text-gray-400` for objective bullets (line 427). This is a one-shade inconsistency in dark mode; not a bug but worth aligning.
