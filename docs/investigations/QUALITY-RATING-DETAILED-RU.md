## 🔍 Детальный Анализ Проблем

### Проблема 1: Почему 3 модели смогли сгенерировать только метадату?

**Пострадавшие модели**:

- qwen3-32b
- qwen3-235b-a22b-thinking-2507
- openai/gpt-oss-120b

**Симптомы**:

- ✅ Test 1 (Metadata EN): SUCCESS - идеальный JSON
- ✅ Test 2 (Metadata RU): SUCCESS - идеальный JSON
- ❌ Test 3 (Lesson EN): `Unexpected token '<', "<html>\r\n<h"... is not valid JSON`
- ❌ Test 4 (Lesson RU): `HTTP 500 Internal Server Error`

**Анализ причин**:

#### 1. Сложность промпта для уроков vs метадаты

**Метадата (простая задача)**:

```
Input: "Introduction to Python Programming"
↓
Output: {
  course_title: "...",
  course_description: "...",
  learning_outcomes: [...]
}
```

- ~533 входных токена
- ~1500 выходных токена
- Простая одноуровневая структура

**Уроки (сложная задача)**:

```
Input: Весь контекст секции + learning objectives + key topics
↓
Output: {
  section: {...},
  lessons: [
    {
      title: "...",
      objectives: [...],
      key_topics: [...],
      exercises: [...]
    },
    {lesson 2},
    {lesson 3}
  ]
}
```

- ~459 входных токена
- ~2000+ выходных токена
- Многоуровневая вложенная структура
- Требует генерации 3-5 уроков с упражнениями

#### 2. Возможные технические причины

**A. Превышение контекстного окна**:

- Модели с меньшим контекстом могут не справляться с вложенными структурами
- qwen3-32b: 32K context
- qwen3-235b-thinking: может иметь ограничения на thinking tokens
- oss-120b: неизвестные ограничения OpenRouter

**B. OpenRouter API ограничения**:

- Lesson generation может превышать max_tokens для некоторых моделей
- HTTP 500 на T4 (Russian Lesson) указывает на серверные проблемы
- Русский язык + сложная структура = больше токенов

**C. Модели переключаются на HTML formatting**:

- Когда модель не уверена, она может вернуться к "safe" формату (HTML)
- Промпт не достаточно ясно указывает "ТОЛЬКО JSON, НЕТ HTML"
- Модели могут интерпретировать "structure" как HTML structure

**D. Недостаточная инструкция по формату**:

- Метадата: простая структура, модели легко понимают
- Уроки: сложная вложенная структура, нужны более детальные инструкции

#### 3. Паттерн ошибок

Все 3 модели показывают ОДИНАКОВЫЙ паттерн:

- T1, T2: ✅ SUCCESS (metadata)
- T3: ❌ HTML response (lesson EN)
- T4: ❌ HTTP 500 (lesson RU)

Это не случайность! Это указывает на:

1. **Системное ограничение** этих моделей для complex nested JSON
2. **OpenRouter infrastructure issue** для lesson generation + Russian language
3. **Prompt engineering problem** - промпт недостаточно строгий

**Симптомы**:

- ❌ T2 (Metadata RU): "Invalid JSON in response"
- ❌ T3 (Lesson EN): HTML вместо JSON
- ❌ T4 (Lesson RU): HTTP 500

**Анализ**:

#### 1. Отличия от working модели (qwen3-235b-a22b-thinking-2507)

**qwen3-235b-a22b-thinking-2507** (WORKING для metadata):

- Модель ID: `qwen/qwen3-235b-a22b-thinking-2507`
- Результат: ✅ T1, T2 SUCCESS
- Особенность: использует thinking tokens перед генерацией

**qwen3-235b-a22b** (BROKEN):

- Модель ID: `qwen/qwen3-235b-a22b`
- Результат: ❌ 0/4 FAILED
- Особенность: НЕТ thinking tokens

**Вывод**: Версия БЕЗ thinking не может генерировать валидный JSON даже для простых задач!

#### 2. Возможные причины полного провала

**A. Модель нестабильна / экспериментальная**:

- `qwen3-235b-a22b` может быть beta-версией
- Возможно, модель еще не готова к production
- OpenRouter может иметь проблемы с routing для этой модели

**B. Формат вывода не настроен**:

- Модель может требовать другого prompt format
- Возможно, нужны специальные system instructions
- JSON mode может не поддерживаться

**C. API endpoint проблемы**:

- Модель может не быть полностью интегрирована в OpenRouter
- Возможны routing issues к реальному backend

**D. Thinking tokens критичны для этой архитектуры**:

- 235B-a22b архитектура может ТРЕБОВАТЬ thinking pass
- Без thinking модель не может правильно структурировать ответ
- Это объясняет, почему thinking-версия работает, а обычная - нет

#### 3. Тайминги проваленных тестов

- T1: 117189ms (117 секунд!) - модель долго "думала", но вернула мусор
- T2: 751ms - быстрый провал
- T3: 1ms - мгновенный провал
- T4: 437ms - быстрый провал

**Интерпретация**:

- T1: Модель пыталась сгенерировать, но не смогла создать валидный JSON
- T2-T4: После первого провала, модель быстро отказывается (circuit breaker?)

### 1. Для моделей, работающих только с метадатой

- Использовать qwen3-235b-thinking ТОЛЬКО для метадаты

- Улучшить промпт для lesson generation
- Добавить explicit instructions: "ONLY JSON, NO HTML, NO MARKDOWN"
- Разбить lesson generation на меньшие чанки
- Попробовать JSON mode API parameter (если поддерживается)

### 2. Prompt Engineering для уроков

**Текущий промпт** (проблемный):

```
Your Task: Expand this section into 3-5 detailed lessons.
**Output Format**: Valid JSON with section and lessons structure
```

**Улучшенный промпт**:

```
CRITICAL INSTRUCTIONS:
1. OUTPUT FORMAT: You MUST return ONLY valid JSON. NO HTML. NO MARKDOWN. NO EXPLANATIONS.
2. Start your response with { and end with }
3. Do not wrap JSON in code blocks or any other formatting
4. Verify JSON syntax before returning

Your Task: Expand this section into exactly 3 detailed lessons.
Return ONLY the JSON object below:

{
  "section": {...},
  "lessons": [...]
}

DO NOT include any text before or after the JSON.
```
