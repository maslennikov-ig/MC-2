# ТЗ: Должностные инструкции — Скилл + Каталог + Лид-магнит

## Context

**Проблема:** У платформы MegaCampus нет лид-магнита. Пользователи сразу попадают на платный `/create`. Нет бесплатного входа для знакомства с платформой.

**Решение:** Каталог готовых должностных инструкций (ДИ) как лид-магнит. Пользователь регистрируется → получает доступ к каталогу ДИ → находит нужную или запрашивает → из ДИ создаёт курс обучения для сотрудника.

**Цепочка ценности:** ДИ → Бриф курса → Курс обучения (платный продукт)

## Принятые решения

| #   | Решение                | Выбор                                                                 |
| --- | ---------------------- | --------------------------------------------------------------------- |
| 1   | Формат ДИ              | Современная функциональная (без юридического формализма)              |
| 2   | Аудитория              | Собственники бизнеса / CEO                                            |
| 3   | Универсальность скилла | Любая должность, любой отдел                                          |
| 4   | Количество блоков      | 18 (максимальный набор)                                               |
| 5   | Модель доступа         | Каталог готовых ДИ + запрос на генерацию новой                        |
| 6   | Регистрация            | Обязательна для доступа к каталогу                                    |
| 7   | ДИ → Курс              | Автоматический бриф: компетенции → модули, KPI → цели обучения        |
| 8   | Каталог                | По отделам/функциям + специализация (B2B/B2C и т.д.)                  |
| 9   | Хранение               | Supabase (таблица `job_descriptions`) + Next.js динамические страницы |
| 10  | Подход                 | Skill-first: скилл → наполнение → веб                                 |

## Часть 1: Скилл `job-description`

### 1.1 Общее описание

Скилл для Claude Code, генерирующий полноценные должностные инструкции поэтапно. Аналог скилла `offer` из проекта aidevteam — многофазный workflow с уточняющими вопросами.

**Путь:** `.claude/skills/job-description/SKILL.md`

### 1.2 Фазы генерации

#### Фаза 0: Входные данные и уточнение

**Вход:** Пользователь говорит название должности (например, "Менеджер по продажам B2B").

**Шаг 0.1: Распознавание должности**

- Определить отдел/функцию (Продажи, Маркетинг, IT, HR, Финансы, Логистика, Производство, etc.)
- Определить уровень (Junior/Middle/Senior/Lead/Director)
- Предложить специализацию через уточняющий вопрос:
  > "Менеджер по продажам — это широкая роль. Хотим конкретизировать? Варианты:
  >
  > 1. B2B продажи (длинный цикл, тендеры, работа с ЛПР)
  > 2. B2C продажи (розница, быстрые сделки, массовый поток)
  > 3. Продажи услуг (консалтинг, IT-услуги, высокий чек)
  > 4. Телефонные продажи (холодные звонки, скрипты)
  > 5. Оставить общим (без специализации)"

**Шаг 0.2: Уточняющие вопросы (3-5 штук)**

Скилл задаёт 3-5 вопросов, адаптированных под конкретную должность:

Примеры для менеджера по продажам:

- "Какой средний чек / цикл сделки?" (влияет на KPI)
- "Кому подчиняется? Есть ли подчинённые?" (влияет на структуру)
- "Какие CRM/инструменты используются?" (влияет на блок инструментов)

Примеры для DevOps-инженера:

- "Какой стек? (AWS/GCP/on-premise)" (влияет на компетенции)
- "Размер команды разработки?" (влияет на масштаб ответственности)
- "CI/CD уже настроен или с нуля?" (влияет на обязанности)

**Правило:** Вопросы адаптируются к должности. Скилл сам решает какие вопросы задать на основании контекста. Максимум 5 вопросов, минимум 3.

**Шаг 0.3: Выбор slug и метаданных**

- Предложить 3 варианта slug (URL-friendly)
- Определить теги: отдел, специализация, уровень
- Определить категорию каталога

#### Фаза 1: Генерация документа (секция за секцией)

**КРИТИЧЕСКИ ВАЖНО:** Документ генерируется секция за секцией, НЕ весь сразу. Каждая секция — отдельный Write/Edit. Между секциями — прогресс-сообщение пользователю.

**Порядок генерации:**

```
Группа 1 (Write): Заголовок + Блоки 1-4 (основа)
Группа 2 (Edit):  Блоки 5-7 (KPI + компетенции + инструменты)
Группа 3 (Edit):  Блоки 8-10 (взаимодействие + карьера + профиль)
Группа 4 (Edit):  Блоки 11-13 (рабочий день + онбординг + мотивация)
Группа 5 (Edit):  Блоки 14-16 (регламенты + red flags + FAQ)
Группа 6 (Edit):  Блоки 17-18 (отраслевой контекст + бизнес-цели)
```

### 1.4 Правила генерации контента

**Язык:**

- Скилл-файл: English (экономия токенов)
- Сгенерированная ДИ: Русский
- Общение с пользователем: Русский

**Стиль для собственника:**

- Простой бизнес-язык, без HR-жаргона
- Каждый блок объясняет "зачем это нужно собственнику"
- KPI — конкретные цифры, не абстрактные "повышение эффективности"
- Обязанности — действия с результатом, не "обеспечивает", "содействует"

**Адаптивность:**

- Блоки 13.3 (Скрипты) — только для ролей с коммуникацией (продажи, поддержка, HR)
- Блок 3.4 (Ежеквартальные) — только для менеджерских ролей
- Блок 12 (Система мотивации) — адаптируется: для продаж — бонусы от KPI; для IT — грейды; для операций — премии
- Блок 16 (Отраслевой контекст) — скилл использует WebSearch если нужно актуальные данные

**Anti-patterns:**

- НЕ генерировать весь документ сразу
- НЕ использовать шаблонные фразы ("ответственный, коммуникабельный")
- НЕ копировать KPI из одной должности в другую
- НЕ давать размытые обязанности ("обеспечивает эффективную работу")
- НЕ пропускать столбец "Как считать" в KPI
- НЕ писать юридическим языком

### 1.5 Фаза 2: Ревью и публикация

**Шаг 2.4:** Подтвердить публикацию — ДИ появляется в каталоге

## Часть 2: База данных

### 2.1 Таблица `job_descriptions`

```sql
CREATE TABLE job_descriptions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  -- Идентификация
  slug TEXT UNIQUE NOT NULL,          -- URL-friendly ID
  title TEXT NOT NULL,                 -- "Менеджер по продажам B2B"

  -- Классификация
  department TEXT NOT NULL,            -- "Продажи", "IT", "HR", "Маркетинг"...
  specialization TEXT,                 -- "B2B", "B2C", "SaaS"...
  level TEXT NOT NULL DEFAULT 'middle', -- junior/middle/senior/lead/director
  tags TEXT[] DEFAULT '{}',            -- свободные теги для фильтрации

  -- Контент
  content_md TEXT NOT NULL,            -- Полный Markdown документа
  summary TEXT,                        -- Краткое описание (1-2 предложения) для карточки в каталоге

  -- Мета для конверсии в курс
  course_brief JSONB,                  -- Автоматически сформированный бриф:
                                       -- { competencies: [], learning_goals: [],
                                       --   suggested_modules: [], target_audience: "" }

  -- Статус
  status TEXT NOT NULL DEFAULT 'draft', -- draft / published / archived

  -- SEO / каталог
  meta_title TEXT,
  meta_description TEXT,

  -- Аудит
  created_by UUID REFERENCES auth.users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  published_at TIMESTAMPTZ,
  view_count INTEGER DEFAULT 0
);

-- Индексы
CREATE INDEX idx_jd_department ON job_descriptions(department);
CREATE INDEX idx_jd_status ON job_descriptions(status);
CREATE INDEX idx_jd_slug ON job_descriptions(slug);
CREATE INDEX idx_jd_tags ON job_descriptions USING GIN(tags);

-- RLS
ALTER TABLE job_descriptions ENABLE ROW LEVEL SECURITY;

-- Все авторизованные пользователи видят опубликованные ДИ
CREATE POLICY "Published JDs are viewable by authenticated users"
  ON job_descriptions FOR SELECT
  TO authenticated
  USING (status = 'published');

-- Администраторы могут всё
CREATE POLICY "Admins can manage all JDs"
  ON job_descriptions FOR ALL
  TO authenticated
  USING (
    EXISTS (
      SELECT 1 FROM users
      WHERE users.id = auth.uid()
      AND users.role IN ('admin', 'superadmin')
    )
  );
```

### 2.2 Таблица `job_description_requests` (запросы на генерацию)

```sql
CREATE TABLE job_description_requests (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id),

  -- Что хочет пользователь
  position_title TEXT NOT NULL,        -- "Тимлид фронтенда"
  department TEXT,                     -- Если знает
  context TEXT,                        -- Доп. информация от пользователя

  -- Статус обработки
  status TEXT NOT NULL DEFAULT 'pending', -- pending / in_progress / completed / rejected
  result_jd_id UUID REFERENCES job_descriptions(id), -- Ссылка на готовую ДИ

  -- Аудит
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  processed_at TIMESTAMPTZ
);

-- RLS: пользователь видит только свои запросы
ALTER TABLE job_description_requests ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users see own requests"
  ON job_description_requests FOR SELECT
  TO authenticated
  USING (user_id = auth.uid());

CREATE POLICY "Users can create requests"
  ON job_description_requests FOR INSERT
  TO authenticated
  WITH CHECK (user_id = auth.uid());
```

## Часть 3: Веб-каталог (Next.js)

### 3.1 Новые страницы

| Маршрут                              | Назначение                        | Доступ                |
| ------------------------------------ | --------------------------------- | --------------------- |
| `/[locale]/job-descriptions`         | Каталог ДИ с фильтрами по отделам | Только авторизованные |
| `/[locale]/job-descriptions/[slug]`  | Страница конкретной ДИ            | Только авторизованные |
| `/[locale]/job-descriptions/request` | Форма запроса новой ДИ            | Только авторизованные |

### 3.2 Каталог (`/job-descriptions`)

**Компоненты:**

- `JDCatalogPage` — основная страница
- `JDDepartmentFilter` — фильтр по отделам (sidebar или tabs)
- `JDCard` — карточка ДИ в списке (title, department, specialization, summary)
- `JDRequestBanner` — баннер "Не нашли нужную? Запросите"

**Фильтры:**

- По отделу (Продажи, IT, HR, Маркетинг, Финансы, Логистика, Производство, Операции)
- По уровню (Junior → Director)
- По специализации (если есть)
- Поиск по названию

### 3.3 Страница ДИ (`/job-descriptions/[slug]`)

**Компоненты:**

- `JDViewPage` — основная страница
- `JDContent` — рендеринг MD в HTML (переиспользовать существующий markdown-рендерер из course viewer)
- `JDSidebar` — TOC (аналогично course viewer)
- `JDCourseCTA` — блок конверсии внизу: "Создать курс обучения из этой ДИ"

**CTA-блок:**

- Кнопка "Создать курс обучения"
- Нажатие → переход на `/create` с query-параметрами:
  - `?from_jd={jd_id}&title=Обучение: {title}&brief={encoded_course_brief}`
- Форма создания курса предзаполняется данными из `course_brief` JSONB

### 3.4 Форма запроса (`/job-descriptions/request`)

Простая форма:

- Название должности (обязательно)
- Отдел (select, необязательно)
- Дополнительный контекст (textarea)
- Кнопка "Запросить"

Запрос сохраняется в `job_description_requests`. Мы видим в админке, генерируем через скилл, привязываем.

### 3.5 Навигация

- Добавить пункт "Должностные инструкции" в хедер (после регистрации)
- На главной странице — секция-тизер каталога

## Часть 4: Конверсия ДИ → Курс

### 4.1 Автоматический бриф (`course_brief` JSONB)

При генерации ДИ скилл также формирует JSON-бриф для курса:

```json
{
  "position_title": "Менеджер по продажам B2B",
  "target_audience": "Новые сотрудники на позицию менеджера по B2B продажам",
  "learning_goals": [
    "Освоить полный цикл B2B-продаж от квалификации до закрытия",
    "Научиться работать с CRM и воронкой продаж",
    "Овладеть техниками переговоров с ЛПР"
  ],
  "suggested_modules": [
    {
      "title": "Основы B2B-продаж",
      "based_on_block": "competencies",
      "skills": ["Квалификация лидов", "Работа с воронкой"]
    },
    {
      "title": "Инструменты и CRM",
      "based_on_block": "tools",
      "skills": ["AmoCRM", "Календарь встреч"]
    },
    {
      "title": "KPI и самоконтроль",
      "based_on_block": "kpi",
      "skills": ["Планирование дня", "Отчётность"]
    }

}
```

### 4.2 Предзаполнение формы `/create`

При переходе с `/job-descriptions/[slug]` на `/create`:

1. Читаем `course_brief` из `job_descriptions`
2. Предзаполняем поля CreateCourseForm:
   - Title → "Обучение: {position_title}"
   - Description → из learning_goals
   - Course size → из course_size
3. Пользователь может отредактировать и запустить генерацию
