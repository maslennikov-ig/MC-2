# План внедрения решений для обхода проблемы "High Demand" в Gemini CLI

Этот документ содержит конкретные шаги по глобальной стабилизации работы Gemini CLI в рамках **пользовательской подписки (Google One AI Premium)**, без перехода на платное корпоративное API или привязки к биллингу GCP. Решения направлены на устранение интерактивных блокировок и обрывов связи.

## 1. Скрипт-перехватчик Expect (Авто-нажатие "1. Keep trying")

**Проблема:** В интерактивном режиме при перегрузке серверов процесс блокируется, требуя ручного ввода "1" (Меню `1. Keep trying / 2. Stop`).
**Решение:** Создать системную утилиту на базе `expect`. Она прозрачно оборачивает вызов `gemini`. Скрипт использует строгое регулярное выражение для поиска конкретной строки меню ошибки, и только при ее обнаружении автоматически отправляет "1". Все остальные вопросы и меню (например, выбор файлов, запросы подтверждения) игнорируются перехватчиком и передаются пользователю.

**Как реализовать:**

1.  **Действие AI:** Я создам системный скрипт `~/.local/bin/gemini-auto` со следующим кодом:

    ```bash
    #!/usr/bin/expect -f

    set timeout -1
    spawn gemini --model gemini-3.1-pro-preview

    expect {
        # СТРОГОЕ регулярное выражение: перехватывает ТОЛЬКО конкретное меню ошибки
        -re "1\\. Keep trying.*2\\. Stop" {
            send "1\r"
            puts "\n\[Expect\] Перегрузка (High Demand). Отправлен сигнал продолжения (1)."
            exp_continue
        }
        eof {
            puts "\n\[Expect\] Сессия завершена."
            exit 0
        }
        # Все остальные сообщения и меню прозрачно выводятся пользователю
        -re "(.*)" {
            exp_continue
        }
    }
    interact
    ```

    Сделаю его исполняемым: `chmod +x ~/.local/bin/gemini-auto`.

2.  **Действие User:** Установить `expect`, если его нет (`sudo apt install expect`). Для работы использовать команду `gemini-auto` вместо `gemini`.

## 2. Разблокировка Preview-моделей (Глобально)

**Проблема:** Экспериментальные модели (например, `gemini-3.1-pro-preview`) могут выдавать ошибку отсутствия административного доступа («Your admin might have disabled...»), что приводит к бесконечному циклу блокировок, несмотря на наличие подписки.
**Решение:** Явное включение preview-функций в глобальных настройках утилиты. _(Уже выполнено)_.

**Как реализовать (если ошибка повторится):**

1.  **Действие User:** Выполнить ручной сброс токенов авторизации:
    ```bash
    rm -rf ~/.gemini/cache
    gemini /auth
    ```

## 3. Интеграция расширения Ralph Wiggum для длительных задач

**Проблема:** При длительном рефакторинге или генерации кода стандартный клиент часто падает с ошибкой 503 или обрывает стриминг. Даже `expect`-скрипт подвержен внутреннему алгоритму экспоненциальной задержки ядра (ожидание между авто-попытками будет расти).
**Решение:** Использование расширения Ralph Wiggum. Оно сохраняет контекст и стейт на локальный диск и автоматически возобновляет работу агента при любых сетевых падениях.

**Как реализовать:**

1.  **Действие AI:** Я установлю расширение глобально для твоего CLI:
    ```bash
    gemini extensions install https://github.com/AsyncFuncAI/ralph-wiggum-extension --auto-update
    ```
2.  **Действие User:** Если `gemini-auto` работает слишком медленно из-за задержек серверов, для запуска сложных задач использовать команду `/ralph-loop`.
    _Пример использования:_
    ```bash
    gemini /ralph-loop "Сделай рефакторинг модуля X. Исправляй ошибки, пока тесты не пройдут." --max-iterations 30
    ```

## 4. Оптимизация размера контекста (Payload Optimization через MCP)

**Проблема:** Загрузка гигантских директорий целиком в промпт вызывает обрыв соединения (TCP-стриминга) серверами Google из-за тайм-аута обработки огромного JSON-payload'а.
**Решение:** Строгая дисциплина передачи контекста и использование семантического поиска.

**Как реализовать:**

1.  **Действие AI:** В рамках текущих и будущих сессий я буду избегать массового чтения файлов "про запас", применяя инструменты точечного поиска (утилиты `grep`, `glob`, `read_file`) и протокол MCP (Model Context Protocol).
2.  **Действие User:** При ручном формировании промптов не использовать макросы, загружающие весь проект или огромные папки целиком (например, отказаться от конструкций вроде `@packages/web/src`). При необходимости анализа больших объемов кода — делегировать задачу мне, чтобы я поэтапно исследовал кодовую базу с помощью профильных инструментов поиска.
