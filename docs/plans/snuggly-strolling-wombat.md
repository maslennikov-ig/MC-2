# Что осталось доделать после эпика стоимости

## Контекст

Эпик `mc2-skwm3` закрыт: LangChain-путь записывает списание, которое назвал
OpenRouter. Проверено платным прогоном (курс `e0de31e4`, 7 из 7 строк
`stage_6_content` урегулированы при вставке против базы 0 из 43).

Живой леджер за три дня подтверждает, что деньги учитываются: платных строк без
цены нет, а все `cost_usd is null` — это узловые сводки (`generator`, `judge`,
`selfReviewer`, `init`, `complete`), которые по правилу эпика цену и не несут.

Осталось четыре хвоста. Один из них — дефект, диагноз которого в тикете неверен,
и настоящая причина хуже записанной.

## 1. `mc2-zwp7f` — курс умирает на строке, которую пишем мы сами

В тикете записано «прозу модели оценивают счётчиком символов». Это не так,
поэтому починка «поправить промпт» ничего бы не дала.

Ход разбора:

- `packages/course-gen-platform/src/stages/stage4-analysis/phases/phase-2-scope-helpers.ts:312`
  — `applyStructureDefaults` **уже** чинит короткое `calculation_explanation`
  перед первым `Phase2OutputSchema.parse`. До этого места ошибка не доходит.
- `phase-2-scope-helpers.ts:338` — второй `parse`, уже **после**
  `normalizeRecommendedStructure`.
- `packages/course-gen-platform/src/shared/course-structure-policy.ts:257` —
  нормализатор **затирает** объяснение модели своей строкой:

  ```
  `${totalLessons} lessons x ${lessonDuration} minutes = ${hours} hours (${profile.label} profile)`
  ```

- `packages/shared-types/src/analysis-schemas.ts:468` — а схема требует
  `min(50)`.

Длина этой строки — функция от чисел и от длины ярлыка профиля. Перебор сетки
(профиль × длительность 3–45 мин × 1–40 уроков) даёт **176 комбинаций короче 50
символов**, все — на профилях явного размера (`micro`, `small`, `medium`,
`large`); длинные ярлыки (`general auto`, `Career Playbook role bridge`) не
попадают никогда. Примеры: `"6 lessons x 10 minutes = 1 hours (micro profile)"`
— 48 символов; `"12 lessons x 10 minutes = 2 hours (micro profile)"` — 49.

Целое число часов теряет два символа (`1` вместо `0.75`), однозначная
длительность — ещё один. Все сохранённые в базе курсы лежат на 50–51 символе, то
есть ровно на границе:

| курс       | объяснение                                            | длина |
| ---------- | ----------------------------------------------------- | ----- |
| `e0de31e4` | `3 lessons x 15 minutes = 0.75 hours (micro profile)` | 51    |
| `6b3b183e` | `3 lessons x 30 minutes = 1.5 hours (micro profile)`  | 50    |

Цена попадания: курс `7b1837c7` оплатил 6 вызовов ($0.004728), из них **четыре**
— `stage_4_scope`, три попытки BullMQ подряд, и умер. Деньги записаны честно
(леджер работает), но потрачены впустую.

### Что делать

1. `course-structure-policy.ts:256` — не затирать прозу модели, а дополнять:
   сохранить исходное объяснение и приписать пересчёт после нормализации. Числа
   модели после нормализации могут быть неверны, поэтому арифметику оставляем —
   но рядом с текстом, а не вместо него.
2. Гарантировать длину конструкцией: собранная строка обязана удовлетворять
   `Phase2OutputSchema` при любых числах и любом ярлыке, включая случай, когда
   модель не дала ничего.
3. Тест в `packages/course-gen-platform/tests/unit/course-structure-policy.test.ts`,
   перебирающий сетку (профили × длительности × число уроков) и проверяющий
   результат схемой. Пример ловит пример; геометрию ловит только перебор.
4. Поправить заметку в `mc2-zwp7f`: причина не в промпте.

Проверка: `pnpm -F course-gen-platform test course-structure-policy phase-2-scope`.
Живой прогон не нужен — дефект детерминирован и воспроизводится юнит-тестом.

## 2. `mc2-a6qxc` — гейт дрейфа проверяет 7 имён, прод ходил на 11

`LIVE_ROUTING_MODEL_IDS` (`packages/shared-types/src/model-catalog.ts:511`) —
список из семи строк, набранный руками. `scripts/check-model-catalog-drift.ts:150`
перечитывает у OpenRouter только его. Остальные шесть моделей, которыми реально
пользовался прод, живут в снапшоте «retired» в
`tests/unit/model-catalog-coverage.test.ts:127` и заморожены навсегда.

Почему это всё ещё важно после эпика: крупные строки теперь несут списание
провайдера, так что каталог перестал быть источником отчётности. Но он остался
**потолком** — `buildProviderPriceCeiling` строит `provider.max_price` из этих
чисел, а потолок ниже всех эндпоинтов это отказ вызова, а не экономия
(`reference_max_price_refuses_the_call`).

Модели попадают на путь вызова из пяти мест в коде, а не из одного списка:

| источник                                                                           | что содержит                                  |
| ---------------------------------------------------------------------------------- | --------------------------------------------- |
| `shared/llm/phase-fallback-config.ts:33`                                           | `modelId` на каждую фазу + `DEFAULT_MODEL_ID` |
| `shared/llm/model-selector.ts:155-250`                                             | своя таблица эскалации (9 ярлыков)            |
| `shared/llm/model-config-db.ts:32`                                                 | карта переименований провайдера               |
| `stages/stage6-lesson-content/config/index.ts:66`, `utils/mermaid-llm-fixer.ts:67` | свои запасные и тировые модели                |
| `config/config-seed.json`                                                          | сид БД (уже выводится в тесте, строка 32)     |

### Что делать

1. Новый модуль `packages/course-gen-platform/src/shared/llm/routable-models.ts`
   с `collectRoutableModelIds()`: объединяет перечисленные реестры **импортом**,
   а не перечислением, и прогоняет каждый id через `normalizeModelId`.
2. `scripts/check-model-catalog-drift.ts:150` берёт этот набор вместо
   `LIVE_ROUTING_MODEL_IDS`. Скрипт остаётся read-only и офлайновым по вызову.
3. `tests/unit/model-catalog-coverage.test.ts` — проверка «у всякой маршрутизуемой
   модели есть цена» переводится на тот же набор. Существующие пробелы
   заносятся в явный список-исключение с причиной, чтобы тест падал только на
   новом (правило «grandfather what exists»).
4. `LIVE_ROUTING_MODEL_IDS` остаётся для потребителей в `shared-types`, но
   перестаёт быть авторитетом: тест проверяет, что он — подмножество выведенного
   набора, иначе он тихо разъедется снова.

Проверка: `pnpm -F course-gen-platform test model-catalog-coverage phase-config-provider-contract`,
затем один живой запуск `pnpm -F course-gen-platform exec tsx scripts/check-model-catalog-drift.ts`
— он покажет реальный дрейф по расширенному набору (на 2026-08-25 их было минимум
два). Числа каталога по итогам этого запуска правим отдельным коммитом, помня,
что цена `deepseek-v4-flash-0731` двигалась в 2.27 раза за два часа: гоняться за
ней руками бессмысленно, замороженное значение нужно только как запас, и там
завышенное безопасно, а заниженное отказывает в вызове.

## 3. `calculatePhaseCost` возвращает `$0` для незнакомой модели

`packages/course-gen-platform/src/shared/llm/cost-calculator.ts:196` — при
отсутствии модели в `OPENROUTER_PRICING` пишет `logger.warn` и возвращает `0`.
«Не измерено» читается как «бесплатно» — ровно та ошибка, что однажды испортила
запрос поиска неоценённых вызовов. Соседний `calculateLlmCostUsd` в
`shared/metrics/llm-cost.ts` возвращает `undefined` именно поэтому.

Тип менять по всей цепочке агрегации не нужно и не стоит: `CostBreakdown`
раздаётся дальше как числа (`orchestrator-helpers.ts:473`,
`stage-career-playbook/nodes/runtime-attempt.ts` через `estimateCost`). Достаточно
повторить приём, уже применённый в этом эпике для `estimateLlmCostUsd`:

- добавить правдивый примитив, возвращающий `number | undefined`;
- `calculateGenerationCost` продолжает суммировать числа, но приносит в
  `CostBreakdown` необязательное поле с перечнем фаз, чью цену измерить не
  удалось;
- `estimateCost`, которым Career Playbook принимает бюджетные решения, перестаёт
  отвечать «бесплатно» на незнакомую модель.

Беды на это нет — завести перед началом.
