# Career Playbook — План приёмки качества

Версия 1 от 2026-08-11.

Задаёт, как доказать, что работа по [плану](../buzzing-jingling-oasis.md) действительно подняла
качество, а не переставила дефекты. База сравнения — представительный прогон 2026-08-11 с
редакторской оценкой **2.6 / 5** (`.codex/stages/mc2-db696.105/evidence/quality-review.md`).

Нормативные правила: [../../career-playbook/quality-contract.md](../../career-playbook/quality-contract.md).

## Три уровня приёмки

| Уровень                           | Стоимость       | Когда                                                | Что доказывает                                                 |
| --------------------------------- | --------------- | ---------------------------------------------------- | -------------------------------------------------------------- |
| L1. Детерминированный скоркард    | $0, секунды     | На каждый коммит, в CI                               | Ни одна из пяти формализованных категорий дефектов не проходит |
| L2. Офлайн-прогон по фикстурам    | $0, секунды     | Перед закрытием задачи A/B/E                         | Правила работают на сохранённом выходе реального прогона       |
| L3. Живой представительный прогон | ~$0.35, ~25 мин | Один раз, задача F2, **только по явной авторизации** | Итоговое качество достигнуто end-to-end                        |

---

## L1. Детерминированный скоркард

Запускается на любом Markdown Role Guide и возвращает структурированный отчёт.

### Входы

- Итоговый Markdown (`final_markdown` или собранные блоки).
- `RoleProfileSpec` — нужен `metric_ledger`, `evidence_ledger`, `generated_on`,
  `business_context.mode`.

### Проверки и пороги

| #   | Проверка                                                                                            | Порог       |
| --- | --------------------------------------------------------------------------------------------------- | ----------- |
| 1   | `validateMetricLedgerConsistency`                                                                   | 0 критичных |
| 2   | `validateUnsourcedStatistics`                                                                       | 0 критичных |
| 3   | `validateExampleMarking`                                                                            | 0 критичных |
| 4   | `validateRelativeDates`                                                                             | 0 критичных |
| 5   | `validateAntiGoalConflict`                                                                          | 0 критичных |
| 6   | Существующие минимумы (анти-цели ≥ 4, решения ≥ 4, режимы отказа ≥ 3, Mermaid-покрытие и синтаксис) | 0 критичных |
| 7   | Язык и плейсхолдеры                                                                                 | 0 критичных |

### Регресс-корпус

Каждая новая проверка обязана иметь два теста на реальных данных из
`packages/course-gen-platform/artifacts/career-playbook-quality/career-playbook.md`:

| Проверка   | Позитивный пример (должна сработать)                         | Негативный (не должна)                    |
| ---------- | ------------------------------------------------------------ | ----------------------------------------- |
| Метрики    | `:46` (≥2×) против `:87` (≥3×)                               | Согласованная пара после исправления      |
| Источники  | `:154` («90-95% accuracy»), `:805` («95% weekly, 65% daily») | То же утверждение со ссылкой `[S1]`       |
| Маркировка | `:500-506` ($120,000/$60,000), `:843` ($50M ARR)             | Значение с маркером `(example — replace)` |
| Даты       | `:393-425` (январь-март 2025)                                | «День 1-30», футер с текущим годом        |
| Анти-цели  | `:32` против `:55-56`                                        | Обязанность, не нарушающая анти-цель      |

Это ключевое требование: проверки пишутся против **уже наблюдавшихся** дефектов, а не против
воображаемых.

## L2. Офлайн-прогон по фикстурам

Набор фикстур `RoleProfileSpec` + сохранённые выходы блоков, на которых прогоняются L1-проверки и
рендер PDF без обращения к LLM.

### Матрица фикстур

| #   | Роль                             | Язык | Режим            | Что покрывает                                                       |
| --- | -------------------------------- | ---- | ---------------- | ------------------------------------------------------------------- |
| 1   | Sales Manager B2B, lead          | en   | universal        | Базовая линия сравнения с прогоном 2026-08-11                       |
| 2   | Руководитель отдела продаж, lead | ru   | universal        | Русская локализация, маркеры примеров по-русски                     |
| 3   | Backend Engineer, middle         | en   | company_specific | Роль без подчинённых, реальный корпус, `provenance: company_source` |
| 4   | HR Business Partner, senior      | ru   | company_specific | Функция без числовых KPI как таковых                                |

Фикстуры хранятся в `packages/course-gen-platform/tests/fixtures/career-playbook/` и не требуют
сети. Фикстура №1 строится прямо из сохранённого артефакта прогона 2026-08-11 — это даёт прямое
сравнение «до / после» на тех же данных.

### PDF-фикстура

Отдельный эталонный Markdown со всеми поддерживаемыми конструкциями: h1-h6, нумерованные,
маркированные и вложенные списки, `hr`, blockquote, GFM-таблица, inline-код, fenced-код,
Mermaid-диаграмма, ссылка, символы ✅/⚠️.

Проверяется:

1. В HTML нет сырого Markdown: ни `^#{1,6} `, ни `^---$`, ни `^\d+\. `, ни `[текст](url)` вне `<a>`.
2. В PDF нет полностью пустых страниц.
3. Ни одна Mermaid-диаграмма не разорвана между страницами.
4. Число пунктов оглавления равно числу блоков; каждый `href` указывает на существующий `id`.

Реализация — расширение `tests/unit/services/career-playbook-pdf.test.ts`.

## L3. Живой представительный прогон

**Платный прогон. Выполняется только по явной авторизации пользователя.**

### Условия воспроизводимости

Тот же сценарий, что и `mc2-db696.105`, чтобы сравнение было честным:

- Фикстура: Sales Manager B2B, sales, lead, подчиняется CRO, ведёт SDR/AE, компания 51-200,
  growth-stage B2B SaaS.
- Язык: английский. Режим: universal. Без загрузок, без course bridge.
- Изолированное окружение: выделенный worker и API, как в прогоне 2026-08-11.
- Потолок расхода задаётся заранее и фиксируется в артефакте прогона.

### Порядок

1. Preflight: `pnpm --filter @megacampus/course-gen-platform smoke:career-playbook:preflight`.
2. Живой прогон: `pnpm --filter @megacampus/course-gen-platform smoke:career-playbook:live`.
3. Сохранить артефакты (Markdown, PDF, обложка, `run-record.json`) и посчитать SHA-256 —
   формат как в `.codex/stages/mc2-db696.105/evidence/artifacts.sha256`.
4. Прогнать L1-скоркард на полученном Markdown.
5. Отрендерить **все** страницы PDF в PNG и просмотреть.
6. Заполнить ручную рубрику (ниже).
7. Полная зачистка тестовых данных по фикстуре и идентификаторам очереди, с отчётом о нулевых
   остатках — как в прогоне 2026-08-11.

### Ручная рубрика

Те же семь измерений, что в исходном ревью, чтобы числа были сопоставимы.

| Измерение                         |    База |     Порог | Что смотреть                                                                                      |
| --------------------------------- | ------: | --------: | ------------------------------------------------------------------------------------------------- |
| Полнота                           |       5 |       ≥ 5 | 26 нумерованных разделов плюс header; все блоки сохранены                                         |
| Согласованность                   |       2 |       ≥ 4 | Совпадение чисел между блоками; отсутствие рекомендаций, противоречащих анти-целям                |
| Практическая польза               |       3 |       ≥ 4 | Шаблоны и чеклисты применимы; значения, требующие калибровки, помечены и собраны в блоке 26       |
| Обоснованность и прослеживаемость |       1 |       ≥ 3 | Каждая точная внешняя цифра несёт `[Sn]`; раздел «Источники» присутствует и ведёт на реальные URL |
| Решения и управление рисками      |       3 |       ≥ 4 | Четыре оси классификации решений; пороги в FMEA согласованы с реестром                            |
| Качество PDF                      |       2 |       ≥ 4 | Нет пустых страниц, сырого Markdown, разорванных диаграмм и квадратов вместо глифов               |
| Обложка                           |       3 |       ≥ 3 | Читается специфика роли, не только «бизнес вообще»                                                |
| **Общая**                         | **2.6** | **≥ 4.0** |                                                                                                   |

### Жёсткие условия, не сводимые к баллам

- L1-скоркард: ноль критичных находок.
- Ноль полностью пустых страниц PDF, ноль фрагментов сырого Markdown.
- Ноль абсолютных календарных дат вне футера блока 25.
- Стоимость ≤ **$0.35**, время ≤ **25 минут**, регенераций ≤ 6.
- `costBreakdown` содержит записи об оборванных по таймауту попытках со стоимостью `unknown`.
- Зачистка подтверждена нулевыми остатками по организациям, пользователям, playbook-ам, задачам,
  файлам, объектам хранилища и ключам очереди.

### Что делать при недостижении порога

Не «подкручивать промпт до зелёного». Порядок такой:

1. Определить, какой контур пропустил дефект: детерминированный, LLM-судья или генератор.
2. Если дефект формализуем — добавить детерминированную проверку и тест на этот конкретный
   пример. Приоритет всегда у детерминированного контура.
3. Если не формализуем — уточнить категорию в таксономии судьи, а не добавлять запрет в промпт
   генератора. Запреты в промптах масштабируются хуже проверок.
4. Завести находку в Beads под `mc2-db696` и повторить L3 только после устранения.

## Артефакты приёмки

По итогам L3 создаётся стейдж-запись по контракту `AGENTS.md`:

- `.codex/stages/<stage_id>/evidence/quality-review.md` — ревью по рубрике выше;
- `.codex/stages/<stage_id>/evidence/artifacts.sha256` — контрольные суммы;
- `.codex/stages/<stage_id>/evidence/scorecard.json` — вывод L1-скоркарда;
- `.codex/stages/<stage_id>/summary.md` — итог, сравнение с базой 2.6 / 5, явные деферы.

Отчёт обязан фиксировать не только результат, но и **что осталось непроверенным** — например,
если внешний поиск был недоступен и режим «без источников» не тестировался в живую.
