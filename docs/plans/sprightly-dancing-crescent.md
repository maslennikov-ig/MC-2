## Context

## Issue 1: Bridge Task Failures

### Root Cause Analysis

Ошибка `bridge task failed (status=failed)` означает:

- Запрос к Python bridge **успешно создан** (task_id получен)
- Фоновая генерация **началась, но упала** внутри `notebooklm-py`
- При поллинге TS-клиент получил `status=failed` → выбросил ошибку

**Причина**: Методы `notebooklm-py` для flashcards, mind_map, infographic **могут не работать** в текущей версии (`>=0.1.0`) или NotebookLM API отклоняет эти запросы. Study guide работает, потому что `generate_report()` — самый стабильный метод в библиотеке.

### Investigation Steps (нужен доступ к bridge логам)

```bash
# 1. Проверить логи bridge на Dev
ssh megacampus-dev "docker logs notebooklm-bridge --tail 200 2>&1 | grep -i 'error\|failed\|traceback'"

# 2. Проверить версию notebooklm-py
ssh megacampus-dev "docker exec notebooklm-bridge pip show notebooklm-py"

# 3. Проверить доступные методы
ssh megacampus-dev "docker exec notebooklm-bridge python -c 'import notebooklm; print(dir(notebooklm.client.artifacts))'"
```

### Fix Strategy

**Если методы не существуют** в `notebooklm-py`:

- Python bridge уже обрабатывает это: `getattr(client.artifacts, "generate_flashcards", None)` → `MediaGenerationError`
- Нужно: улучшить error message в TS handlers, чтобы пользователь видел понятную ошибку, а не "task failed"
- Временно: скрыть нерабочие типы из UI, оставив только `nlm_study_guide`

**Если методы существуют, но падают** на NotebookLM API:

- Проверить error details в bridge logs
- Возможно: NotebookLM API ограничивает типы артефактов (не все аккаунты имеют доступ ко всем типам)
- Fix: добавить retry с exponential backoff внутри generator.py, или улучшить error reporting
