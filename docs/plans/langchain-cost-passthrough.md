# Стоимость вызова на LangChain-пути

## Задача

Генерация уроков Stage 6 — самая дорогая строка курса — идёт через LangChain и
не знает, сколько стоил вызов. Надо, чтобы знала, из того же ответа, из которого
это уже узнал SDK-путь.

## Что уже сделано (контекст, не работа)

Коммит `1b6aefc97`. OpenRouter кладёт реальную стоимость в тело каждого ответа:

```
usage: { prompt_tokens: 13, completion_tokens: 5, cost: 0.000004257, ... }
```

Измерено на живом API 2026-08-25: приходит всегда, и без
`usage: {include: true}`, и совпадает с `GET /api/v1/generation` до цифры.
`parseCompletionResponse` теперь её читает, и SDK-путь пишет в леджер настоящую
цену, а не оценку.

Порядок источников на SDK-пути: названная стоимость → ставка запиненного
эндпоинта → каталог.

## Почему LangChain-путь остался в стороне

`@langchain/openai` строит `llmOutput` из трёх полей, отобранных руками
(`dist/chat_models/completions.js:134`):

```js
llmOutput: { tokenUsage: {
  promptTokens: usageMetadata.input_tokens,
  completionTokens: usageMetadata.output_tokens,
  totalTokens: usageMetadata.total_tokens } }
```

`cost` не может выжить. Это задокументированное намеренное поведение, а не баг:
`ChatOpenAI` реализует спецификацию OpenAI и отбрасывает расширения сторонних
провайдеров. Проверено живым вызовом — стоимости нет ни в `llmOutput`, ни в
`response_metadata`, ни в `usage_metadata`.

Отложенный чек `GET /api/v1/generation` эту дыру не закрывает: ему нужен
`generationId`, а из 92 неурегулированных строк за две недели до 2026-08-25 он
был захвачен **у одной**. По `stage_6_content` — 13 строк, идентификатор у одной.

## Почему не переходим на `@langchain/openrouter`

Официальная рекомендация LangChain — брать провайдерский пакет. Пакет для JS
существует (`@langchain/openrouter@0.4.10`), совместим по peer-зависимостям
(`@langchain/core ^1.0.0` при наших `^1.1.48`) и **действительно пробрасывает
стоимость** — `dist/chat_models/index.js:294` кладёт сырой `usage` целиком:

```js
llmOutput: {
  tokenUsage: data.usage;
}
```

Проверено живым вызовом: `cost: 0.000008514` на месте.

**И тем не менее нет.** `ChatOpenRouter extends BaseChatModel`, а не `ChatOpenAI`,
и ходит в сеть **глобальным `fetch`** напрямую: три голых `await fetch(...)` в
`dist/chat_models/index.js:273,303,338`. Ни `configuration.fetch`, ни любого
другого способа подменить транспорт в типах нет.

А на `configuration.fetch` у нас висит четыре механизма, каждый написан после
реального инцидента:

| обёртка                               | зачем                                  | цена потери                                             |
| ------------------------------------- | -------------------------------------- | ------------------------------------------------------- |
| `instrumentFetchWithGenerationId`     | ловит `x-generation-id` из заголовков  | прерванный вызов снова становится невидимым (mc2-64n8i) |
| `guardAgainstEmptyCompletion`         | ловит непригодное тело                 | пустой ответ снова проходит как успех                   |
| `withFlexCapacityFallbackFetch`       | отказ flex → повтор по обычному тарифу | фаза падает вместо удорожания (mc2-a9w19)               |
| `withMandatoryReasoningRecoveryFetch` | модель требует reasoning → понижение   | вызов падает вместо восстановления                      |

Обмен «четыре работающих механизма за одно поле» невыгоден, тем более что то же
поле достижимо из обёртки, которая уже есть.

Единственный способ сохранить обёртки с этим пакетом — патчить `globalThis.fetch`
глобально, что затронет весь процесс. Не рассматриваем.

**Если пакет добавит опцию `fetch`** — решение стоит пересмотреть: он вернёт
заодно `provider` и `reasoning_details`, которые сейчас тоже теряются. Апстрим-issue
на это стоит завести.

## Решение

Читать `usage.cost` в обёртке транспорта, которая уже читает тело.

`guardAgainstEmptyCompletion` (`empty-response-guard.ts:119`) уже забирает тело
целиком как текст и переупаковывает `Response`. Разбор JSON там почти бесплатен.

### Как доставить стоимость до колбэка

Не через `AsyncLocalStorage`: слот пришлось бы открывать на 11 местах вызова, и
это ровно тот механизм, от которого на LangChain-пути сознательно отказались.

Не через состояние инстанса: `withConfig` пересобирает модель из конструкторных
полей, и всё навешенное теряется клоном `withStructuredOutput` (langchainjs#8586).

**Корреляция по идентификатору генерации.** Тело ответа содержит и `id`, и
`usage.cost`. Колбэк уже достаёт тот же `id` из сообщения — `generationIdOf()` в
`model-cost-callbacks.ts`. Значит обёртка кладёт `id → cost` в ограниченную
карту, а колбэк забирает по ключу, который у него уже есть.

Ни слота, ни состояния инстанса, ни гонки при параллельных вызовах: ключ
уникален для вызова.

### Границы

- Карта **ограничена по размеру** и вычищает запись при чтении. Иначе это
  утечка памяти в воркере, который живёт неделями.
- Промах по ключу — не ошибка. Колбэк ведёт себя как сегодня: оценка по каталогу
  и отложенный чек.
- Стоимость `0` — это измерение, а не «нет данных». `=== undefined`, не falsy
  (mc2-y452l).
- Обёртка **ничего не записывает в леджер сама**. Записывает по-прежнему колбэк,
  иначе появится двойной учёт.

## Приёмка

1. `pnpm type-check`, `pnpm build`, `pnpm -F course-gen-platform test`.
2. Юнит-тест: обёртка кладёт стоимость, колбэк её забирает, запись уходит с
   `billedByProvider` при вставке.
3. Юнит-тест: промах по ключу оставляет сегодняшнее поведение.
4. Юнит-тест: карта не растёт — запись исчезает после чтения.
5. **Живой прогон одного микрокурса на dev** и SQL, а не ощущение:

```sql
select phase,
       count(*) rows,
       count(*) filter (where output_data->>'billedByProvider' = 'true') settled,
       round(sum(cost_usd)::numeric, 6) total
from generation_trace
where course_id = '<id>' and cost_usd is not null
group by 1 order by rows desc;
```

Ожидаем `settled = rows` на `stage_6_content`. Сегодня там 13 строк из 13
неурегулированных.

## Что сюда не входит

- Перевод на `@langchain/openrouter` — см. выше.
- `calculatePhaseCost` возвращает `$0` для неизвестной модели вместо
  «не измерено». Отдельная задача, меняет тип возврата по цепочке агрегации.
- Покрытие дрейф-гейта (`mc2-a6qxc`).
