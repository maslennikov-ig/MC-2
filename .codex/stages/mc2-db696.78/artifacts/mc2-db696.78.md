# Summary

Development CSP no longer emits browser-invalid partial-IP wildcards. It keeps stable localhost
and `.local` sources, then adds only exact origins derived from existing backend and Supabase URLs,
including their matching WebSocket schemes.

# Scope / Routing

The helper is development-only through the existing `NODE_ENV` branch. Broad `http:` or `ws:`
scheme sources were rejected because they would weaken the policy. No production header, secret,
permission, or live environment changed.

# Verification

The initial focused test failed on the legacy `10.*`, `192.168.*`, and `172.16.*` through
`172.31.*` entries. After the fix, helper tests, focused lint, the synthetic Chromium scenario,
full type-check, and full build pass. The browser assertion inspects the real console output.

# Delivery / Cleanup

Accepted in the primary `develop` worktree. No delegated branch or child worktree exists.

# Risks / Follow-ups / Explicit Defers

An unconfigured arbitrary LAN host is intentionally not permitted. Operators must use one of the
existing backend or Supabase URL settings so the exact origin can be admitted safely.
