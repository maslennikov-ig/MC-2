# Summary

Frontend polling was implemented over the existing tRPC `generation.getStatus` query. The page starts polling only on the completion phase while the playbook status is `generating`, stops on terminal status, and guards against overlapping in-flight polls.

The store now tracks `generationStatusError`, `generationProgress`, and `finalMarkdown`, exposes `refreshCareerPlaybookGenerationStatus`, and keeps transient polling failures separate from terminal backend failures. Completion UI shows in-progress/completed/failed states and disables edit navigation while generation is active.

Local integration rejected direct trust in the worker output and reimplemented the behavior through the repo tests.
