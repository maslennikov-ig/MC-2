### Fixed

- 🎨 **Исправлена проблема с отображением Header в тёмной теме на страницах курсов**
  - **Проблема**: Header отображался в тёмном стиле на всех страницах, включая страницы курсов
  - **Решение**:
    - Компонент Header теперь принимает параметр `darkMode` (по умолчанию `false`)
    - Тёмный стиль применяется только на главной странице и странице создания курса
    - На остальных страницах Header адаптируется к текущей теме приложения
  - **Результат**: Правильное отображение Header согласно дизайну каждой страницы

- 🐛 **Исправлена ошибка Hydration при отображении времени в прогрессе генерации**
  - **Проблема**: Несовпадение форматирования времени между сервером и клиентом вызывало ошибку hydration
  - **Решение**: Заменена функция `toLocaleTimeString()` на кастомную `formatTime()` с единым форматом `HH:MM:SS`
  - **Результат**: Устранены ошибки hydration на странице генерации курса

- 🚀 **Исправлена критическая проблема с обновлением статуса генерации курса в реальном времени**
  - **Проблема**: Статус генерации курса не обновлялся на фронтенде, несмотря на успешные вызовы webhook из n8n
  - **Причина**:
    - Дублирующиеся RPC функции в Supabase с разными типами параметров (`jsonb` и `text` для `p_error_details`)
    - Неправильные ссылки на `course_id` в RPC нодах n8n workflow
  - **Решение**:
    - Удалена дублирующая RPC функция с параметром `p_error_details` типа `text`
    - Оставлена единственная версия функции с `p_error_details` типа `jsonb`
    - Исправлены все RPC ноды в Test-RPC workflow для использования корректной ссылки: `$('Get Course from DB').item.json.id`
  - **Результат**:
    - ✅ Статус генерации успешно обновляется в реальном времени
    - ✅ Все 5 шагов прогресса (20%, 40%, 60%, 80%, 100%) корректно отображаются
    - ✅ Протестировано на двух успешных генерациях курсов
    - ✅ n8n логи показывают успешное выполнение всех RPC вызовов
  - **Тестовый workflow**: Test-RPC (ID: RM3Kjcw6UbfawaFO)

### Changed

  - **Проблема**: RPC вызовы из n8n workflows не работали из-за неправильного формата тела запроса
  - **Причина**: n8n использовал `bodyParameters` вместо `specifyBody: "json"` с `jsonBody`
  - **Решение**:
    - Исправлен формат RPC нод для корректной работы с Supabase
    - Упрощена система с 6 шагов до 5, исключив опциональные этапы обработки документов и суммаризации
    - Обновлена RPC функция `update_course_progress` в Supabase для работы с 5 шагами
  - **Обновленные компоненты**:
    - `components/course/generation-progress.tsx` - UI теперь показывает 5 шагов
    - `app/actions/courses.ts` - инициализация создает 5 шагов вместо 6
    - `app/api/webhooks/coursegen/route.ts` - обработка webhook для 5 шагов
  - **Новые 5 шагов**:
    1. Инициализация (Rocket)
    2. Анализ задачи (Brain)
    3. Генерация структуры (BookOpen)
    4. Создание контента (Sparkles)
    5. Финализация (CheckCircle)
  - **Документация**: создан файл `workflows under work/rpc_nodes_5_steps_SIMPLE.md` с готовыми нодами для n8n
  - **Преимущества**:
    - Только 5 RPC нод вместо 7-8
    - Каждый новый workflow автоматически отмечает завершение предыдущего шага
    - Нет дублирования и переусложнения логики
    - Последовательное обновление статусов: 1→2→3→4→5

### Fixed

- 🐛 **Исправлена ошибка двойного пути в n8n webhook URL**
  - Проблема: При вызове webhook добавлялся `/generate` к URL, который уже содержал этот путь
  - Результат: n8n возвращал 404 ошибку "The requested webhook 'POST coursegen/generate/generate' is not registered"
  - Решение: Убрано добавление `/generate` в коде, используется полный URL из переменной окружения
  - Файл: `app/actions/courses.ts` строка 304
  - Статус: Webhook теперь доступен, но требуется настройка авторизации (403 "Authorization data is wrong!")
  - **Требуется действие**: n8n webhook требует Basic Auth, нужны правильные учетные данные для `flow8n.ru`
  - Добавлен код поддержки Basic Auth в `app/actions/courses.ts` (переменные N8N_WEBHOOK_AUTH_USER и N8N_WEBHOOK_AUTH_PASS)

### Fixed

- 🔐 **КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ**: Решена проблема с серверной аутентификацией (SSR)
  - Проблема: сервер не мог прочитать состояние аутентификации, хотя клиент был залогинен

  - Требуется очистка браузерных данных и повторный вход после обновления
