# Pinned exactly, not a floor. `notebooklm-py>=0.1.0` let the build date decide
# the version: the `:latest` image built 2026-08-10 got 0.8.0, the `:develop`
# image built 2026-06-04 got 0.6.0, and on 2026-08-22 production and dev were
# two minor versions apart with nobody having chosen either. 0.8.0 is a breaking
# release — error handling restructured, dict-subscript and get-returns-None
# access removed — so crossing it must be a decision with a run behind it.
# 0.8.0 is what production already carries. The move to 0.8.1 is mc2-rmbwo and
# needs a real generation to verify, which needs the geo-bypass hop back up.
notebooklm-py[headless]==0.8.0
# The `[headless]` extra above is what makes master-token auth possible: without
# it `notebooklm._auth.master_token` refuses at import with "Master-token auth
# needs gpsoauth", so neither the one-time exchange nor the recurring re-mint can
# run inside this image. Verified missing on 2026-08-24 in the running dev
# container and in a local venv alike — `import gpsoauth` raised
# ModuleNotFoundError in both.
#
# Bounded explicitly because the extra itself declares only `gpsoauth>=1.1.0`,
# and a floor is not a range: a rebuild today would silently take 2.0.0, which is
# exactly how this image ended up two minors apart from production before.
# 2.x is the deliberate choice rather than the 1.x the floor was written against.
# `exchange_token` and `perform_oauth` — the only two functions notebooklm-py
# calls — have byte-identical signatures in 1.1.1 and 2.0.0, so the major bump is
# not about them: 1.x caps `urllib3<2.0` and 2.x does not. This image has no
# urllib3 at all today, so pinning 1.x would import that cap for nothing.
gpsoauth>=2.0.0,<3.0.0
