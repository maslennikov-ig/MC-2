# Repository migrations knowingly absent from `supabase_migrations.schema_migrations`.
#
# Used by `scripts/check-migration-drift.ts`. Anything NOT listed here that has no history
# row is treated as a migration that was written and then lost — which is exactly what
# happened to `drop_legacy_restart_from_stage_overload`: it sat unapplied for four months
# under a green gate while the overload it removes broke every `restart_from_stage` RPC
# call (mc2-wxvyr, mc2-y23na).
#
# Format: `<slug><TAB><reason>`. The slug is the filename with `.sql` and every leading
# `<timestamp>_` prefix stripped — the same reduction `slugify()` applies to both sides.
# Record WHY, not just THAT.
#
# The 86 entries below were audited on 2026-08-20 by checking, for each migration, whether
# its EFFECT is present in the database — tables, indexes, functions, types, triggers,
# views, columns, publication membership, nullability — rather than whether its name is in
# the history. Name matching is what the history is bad at; effects are what actually
# matter. Two migrations failed that audit and are absent from this list on purpose:
#   - `add_storage_quota_functions` was genuinely missing and is now applied (mc2-mg8un);
#   - `drop_legacy_restart_from_stage_overload` is superseded, recorded below.
#
# Adding an entry here is a decision, not paperwork. If you cannot say why the database is
# correct without it, apply the migration instead.
