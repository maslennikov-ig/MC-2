---

Runtime: Codex CLI, ChatGPT 5.6.
Target: `/home/me/code/mc2`, ветка `develop`.
Audience: агент-исполнитель с правом менять код репозитория.

Goal: разделить Role Guide по трём адресатам и сделать повторы между блоками
измеримыми, по `specs/028-role-guide-audiences/spec.md`. Прочитай спецификацию
первой, затем `AGENTS.md`, `.codex/orchestrator.toml`, `.codex/handoff.md`,
`.codex/repository-failure-modes.md`.

Context: две задачи владельца от 2026-07-29, обе открыты — повторы между блоками
(`mc2-1786710716114-26-01631777`) и разделение по адресатам
(`mc2-1786710715922-25-db11a6c5`). Измерено 2026-08-29: адресата в генераторе нет
вообще; дословных повторов почти нет (0.8% общих пятисловок между блоками), то
есть дублируется смысл и строковая дедупликация бесполезна. Механизм против
повторов существует, но его середина — `do_not_repeat` — сочиняется LLM: от 0.6
записи на блок до 26. Канонический список тем уже в коде
(`career-playbook-block-topics.ts`); границы выводить из него.

Решение владельца: повторов не должно быть ВНУТРИ представления; МЕЖДУ
представлениями повтор допустим, их читают разные люди. Значит единица гейта —
представление: пара блоков сравнивается, только если оба в одном документе.

Порядок фаз обязателен: 0 (замер) → A (адресность) → B (повторы). A задаёт
множество, внутри которого повтор считается.

Constraints:

- Миграции схемы, reindex, секреты, доступы, force-push запрещены. Представления
  собираются на лету из `generated_blocks`.
- Базовую линию снять ДО правок и сохранить в `docs/`.
- Один платный прогон на dev, артефакт читается глазами (`mc2-db696.110`). Расход
  плейбука — в `career_playbooks.cost_breakdown`; в `generation_trace` его нет.
- Каноническую 26-блочную раскладку не менять (`mc2-1slzl`).
- Разметка адресатов в §3 спеки — предложение. Меняешь галочку — скажи и обоснуй.
- `AGENTS.md` переписывается хуком `bd`: коммить явными путями, не `git add -A`.

Output: код в `develop` обычными коммитами; базовая линия и итоговый замер — в
`docs/`; обе задачи закрыты в Beads с числами в причине закрытия; отчёт в конце —
что изменилось в цифрах против базовой линии.

Success criteria: три представления читаются как законченные документы;
объединение трёх равно полному набору блоков; `do_not_repeat` не зависит от
ответа модели и сужен до блоков одного представления; доля слишком близких пар
внутри представления и внутриблочная близость абзацев ниже базовой линии;
`pnpm type-check` и `pnpm test:unit` зелёные.

Stop: останавливайся и спрашивай, если базовая линия не показала повторов (тогда
неверна метрика, а не пайплайн); если для приёмки нужен второй платный прогон;
если разметка адресатов оставляет какой-то документ бессодержательным; если
требуется миграция схемы. Не закрывай задачу по признаку «выглядит сделанным».
